# Custom Renderer (Windows) — live sharp upscale + in-game menu

Status: **implemented and verified** (2026-11-17). Part of the
`v0.0.2-experimental` line. This document records what was studied from other
static-recomp ports, what was built, and the honest scope.

## Why

At default, the guest renders at 1280x720 and the host stretches that to the
window (e.g. 1920x1080 fullscreen) with bilinear filtering — visibly soft.
Xenia Canary and the other recomp ports (CoD3Recomp, Edge of Time, etc.) look
sharp because their present path uses a **high-quality upscale** (Lanczos,
Catmull-Rom, FSR/CAS) instead of bilinear.

## What was studied

Custom renderers in `CoD3Recomp` (`CoD3Host/render_d3d11.cpp`,
`docs/renderer.md`), `EdgeOfTimeRecomp` (`src/gpu/blit` shaders,
`settings.cpp`), and `xenia-canary` (`ui/shaders/guest_output_*`). Common
pattern: resolution scale is a multiplier on render-target allocation, and a
sharp upscale shader (Lanczos2/Catmull-Rom/CAS) runs at present.

An important finding: **even these ports require a restart to change the
internal render scale** (e.g. Edge of Time's `eot_render_scale` is
`kRequiresRestart`). What is genuinely live is the **present upscale filter**
and post effects. So the live, no-restart lever is the upscale stage — which is
exactly what was implemented here.

## What was built

A **Lanczos2 guest-output upscale pipeline** in the D3D12 presenter:

- `renderer/shaders/guest_output_lanczos_ps.hlsl` — a 9-tap Lanczos2 upscale
  matching ReXGlue's guest-output root signature (t0 source, b0 constants
  `output_offset`/`output_size_inv`, s0 linear sampler). Compiled with
  `fxc /T ps_5_1` to DXBC (`make_header.py` produces the byte header).
- `third_party/.../host/shaders/bytecode/d3d12_5_1/guest_output_lanczos_ps.h` —
  generated bytecode.
- `presenter.h`: `GuestOutputPaintEffect::kLanczos` + a live string setting
  `gpu.xenos.present_upscale` (allowed: `bilinear`, `lanczos`; default
  `lanczos`, **no `kRestart`**).
- `d3d12_presenter.h/.cpp`: pipeline for kLanczos, `SupportsLanczosUpscale()`
  override (D3D12 only — Vulkan/Android stays bilinear).
- `presenter.cpp`: selects kLanczos each frame when upscaling and the setting
  is `lanczos`; logs `BS1-RENDERER present_upscale=...` on change.

### Live controls (no restart)
- **F4** — built-in settings overlay; `gpu.xenos.present_upscale` appears as a
  combo and changes take effect immediately (config is rebuilt every frame).
- **F2** — hotkey that toggles bilinear <-> lanczos live.
- **F1** — cycles internal draw scale 1x/2x/3x; this still needs a title reload
  (same as the reference ports), so it is not part of the live path.

## Verification (evidence)

```
BS1-RENDERER present_upscale=bilinear
[BS1] upscale -> lanczos (live, no restart)
```
The setting changed from bilinear to lanczos with **no "restarting title"
message** and the pid stayed alive; no pipeline/effect errors. The Lanczos
pipeline compiled and rendered a visibly sharp 1920x1080 title screen (captured
during testing). `python scripts/verify-all.py` -> 12/12 PASS.

## Honest scope

This is a **present-stage custom upscale stage**, not a ground-up rewrite of the
Xenos GPU backend. A full custom renderer like CoD3Recomp's (a ~500 KB D3D11
backend with its own shader translator) is a much larger project and is not what
ships here. The delivered change achieves the user-visible goals — a clear,
sharp image and live in-game control of the upscale with no restart — using the
existing ReXGlue D3D12 pipeline as the base.
