# Custom Xenos Renderer (Windows D3D11 + Android OpenGL ES 3.2)

Status: **implemented and verified through `v0.0.5-experimental`** (2026-11-19).
This document records what was studied from other static-recomp ports, what was
built for both **Windows (D3D11)** and **Android (OpenGL ES 3.2)**, and the live
resolution scaling and performance architecture.

## Why

At default, the guest renders at 1280x720 and the host stretches that to the
window (e.g. 1920x1080 fullscreen) with bilinear filtering — visibly soft.
Xenia Canary and the other recomp ports (CoD3Recomp, Edge of Time, etc.) look
sharp because their present path uses a **high-quality upscale** (Lanczos,
Catmull-Rom, FSR/CAS) instead of bilinear.

## What was studied

Custom renderers in `CoD3Recomp` (`CoD3Host/render_d3d11.cpp`,
`docs/renderer.md`), `EdgeOfTimeRecomp` (`src/gpu/blit` shaders,
`settings.cpp`), and `xenia-canary` (`ui/shaders/guest_output_*`). Common
pattern: resolution scale is a multiplier on render-target allocation, and a
sharp upscale shader (Lanczos2/Catmull-Rom/CAS) runs at present.

An important finding: **even these ports require a restart to change the
internal render scale** (e.g. Edge of Time's `eot_render_scale` is
`kRequiresRestart`). What is genuinely live is the **present upscale filter**
and post effects. So the live, no-restart lever is the upscale stage — which is
exactly what was implemented here.

## What was built

A **Lanczos2 guest-output upscale pipeline** in the D3D12 presenter:

- `renderer/shaders/guest_output_lanczos_ps.hlsl` — a 9-tap Lanczos2 upscale
  matching ReXGlue's guest-output root signature (t0 source, b0 constants
  `output_offset`/`output_size_inv`, s0 linear sampler). Compiled with
  `fxc /T ps_5_1` to DXBC (`make_header.py` produces the byte header).
- `third_party/.../host/shaders/bytecode/d3d12_5_1/guest_output_lanczos_ps.h` —
  generated bytecode.
- `presenter.h`: `GuestOutputPaintEffect::kLanczos` + a live string setting
  `gpu.xenos.present_upscale` (allowed: `bilinear`, `lanczos`; default
  `lanczos`, **no `kRestart`**).
- `d3d12_presenter.h/.cpp`: pipeline for kLanczos, `SupportsLanczosUpscale()`
  override (D3D12 only — Vulkan/Android stays bilinear).
- `presenter.cpp`: selects kLanczos each frame when upscaling and the setting
  is `lanczos`; logs `BS1-RENDERER present_upscale=...` on change.

### Live controls (no restart)
- **F4** — built-in settings overlay; `gpu.xenos.present_upscale` appears as a
  combo and changes take effect immediately (config is rebuilt every frame).
- **F2** — hotkey that toggles bilinear <-> lanczos live.
- **F1** — cycles internal draw scale 1x/2x/3x; this still needs a title reload
  (same as the reference ports), so it is not part of the live path.

## Verification (evidence)

```
BS1-RENDERER present_upscale=bilinear
[BS1] upscale -> lanczos (live, no restart)
```
The setting changed from bilinear to lanczos with **no "restarting title"
message** and the pid stayed alive; no pipeline/effect errors. The Lanczos
pipeline compiled and rendered a visibly sharp 1920x1080 title screen (captured
during testing). `python scripts/verify-all.py` -> 12/12 PASS.

## Honest scope

Note: this was the initial D3D12 present-stage upscale layer. It has now been
superseded on Windows (`WIN32`) by a **complete custom D3D11 Xenos renderer
module** (`rexgpu-xenos-custom` / `librexgpu-xenos-customd.dll`) under
`renderer/src/`, providing true **live, no-restart internal resolution scaling**
(`360p` -> `720p` -> `900p` -> `1080p` -> `1440p` -> `2160p`, or custom
`50%-400%` scale) in addition to live `present_filter` (`lanczos` / `bilinear`),
`anisotropy`, `msaa`, `fxaa`, `letterbox`, and `vsync`.

## Standalone Custom D3D11 Xenos Backend (`renderer/src/`)

- **Driver module:** `renderer/CMakeLists.txt` builds shared driver module
  `rexgpu-xenos-custom` (`CustomXenosProvider : rex::IDriverModule`), wired into
  `BioShock1App::OnConfigure` as the default Windows `gpu.driver` (`"custom"`),
  with `--gpu.driver=d3d12` retained as a runtime fallback.
- **Xenos -> HLSL 5.0 translator:** `xenos_hlsl.{h,cpp}` + `render_shaders.{h,cpp}`
  translate guest Xenos microcode into HLSL 5.0 and compile/cache via `d3dcompiler_47.dll`.
- **Live resolution control (`gpu.custom.*`):** `custom_settings.h` registers
  `gpu.custom.internal_resolution` (`360p`, `720p`, `900p`, `1080p`, `1440p`,
  `2160p`, `scale`; default `1080p`), `gpu.custom.resolution_scale_pct` (`50-400`),
  `gpu.custom.present_filter`, `gpu.custom.anisotropy`, `gpu.custom.msaa`,
  `gpu.custom.fxaa`, `gpu.custom.letterbox`, and `gpu.custom.vsync`.
- **No-restart resize path:** `CustomXenosGraphicsDriver::ApplyLiveSettings` updates
  `RenderResources` requested scale/MSAA before `RenderResources::BeginFrame`
  rebuilds host color/depth render targets and resolved textures on the next frame
  boundary with zero title restart.
- **Controls & CLI:** **F1** cycles `360p -> 720p -> 1080p -> 1440p -> 2160p` live;
  **F2** toggles `lanczos` / `bilinear` live; **F4** edits all `gpu.custom.*`
  settings in the overlay; `.\run-windows.ps1` accepts `-InternalResolution`,
  `-Scale`, and `-Driver custom|d3d12`.
- **`v0.0.3-experimental` stability & performance fixes:**
  - Async FIFO FXC shader compilation (`D3DCOMPILE_OPTIMIZATION_LEVEL0` +
    synchronous disk-cache fast path + non-blocking 3D draw fallback) and fast
    word-swapped texture untiling for smooth scene streaming.
  - Strict D3D11 binding hygiene (`ForgetBindings()` explicitly unbinds RTVs,
    PS/VS SRVs, PS, and GS; explicit bound flags; no mid-frame `EndPresent()`
    state clobbering) fixing multipass depth-only / `discard` flickering.
  - Xenos PM4/state fixes: indexed DMA `sourceSelect` bit shift `(initiator >> 6) & 3`,
    `DepthClipEnable`, dual-face cull skip, `RB_STENCILREFMASK_BF`, `kD24FS8`
    depth clear decode, `vfetch_mini` slot inheritance, `precise` VS position
    invariance, and R<->B / channel-replication texture swizzles.

## Standalone Custom OpenGL ES 3.2 Xenos Backend for Android (`renderer/src/gles3/`)

Introduced in `v0.0.4-experimental` and optimized in `v0.0.5-experimental`, the
Android build compiles `rexgpu-xenos-custom` against **OpenGL ES 3.2 + EGL**
(`android_custom_driver.cpp`, `gles3_backend.cpp`, `gles3_resources.cpp`,
`gles3_shaders.cpp`, `xenos_glsl.cpp`):

- **Xenos -> GLSL ES 3.20 translator (`xenos_glsl.{h,cpp}`):** Translates guest
  Xenos vertex and pixel microcode directly into `#version 320 es` shaders with
  hardware vertex fetch, ALU/control-flow emulation, and a persistent on-device
  binary program cache (`glGetProgramBinary` / `glProgramBinary`).
- **Live no-restart internal resolution scaling (`360p`–`1440p`):** The on-screen
  **RES** pill cycles `360p -> 540p -> 720p -> 1080p -> 1440p` live via JNI
  (`nativeSetInternalResolution`). Fresh Android installs default to **`540p`**
  with **`2x` anisotropic filtering** for smooth frame rates across mid-range and
  flagship mobile GPUs.
- **Depth resolve & underwater lighting (`gles3_backend.cpp`):** Depth resolves
  use `GL_NEAREST` filtering and replicate the resolved depth value across all
  four channels (`RRRR`) so BioShock's spotlights, shadow projections, and
  Rapture underwater fog shaders sample accurate depth regardless of whether the
  Xenos fetch swizzle selects `.r`, `.g`, `.b`, or `.a`.
- **Bink video fast-path & tiered texture change-detection (`gles3_resources.cpp`):**
  - Linear (untiled) 2D texture levels use a fast row-by-row `memcpy` path in
    `LinearizeLevel`, eliminating per-texel loops during Bink video playback
    (such as Andrew Ryan's elevator projection speech).
  - Texture memory fingerprinting is tiered: dynamic and uncompressed video
    textures are checked every frame so 30 fps Bink movies never stall or flicker
    on 90–120 Hz screens, whereas static compressed level textures back off after
    consecutive unchanged checks.
  - Per-frame texture GC eviction is capped so level streaming does not cause
    frame-time spikes.
- **Display-priority GPU worker & sustained performance (`android_custom_driver.cpp`):**
  - The GPU command processor thread boosts its scheduling priority to Android
    display priority (`setpriority(PRIO_PROCESS, 0, -8)` with fallback to `-4`),
    paired with `window.setSustainedPerformanceMode(true)` and
    `android:appCategory="game"`.
